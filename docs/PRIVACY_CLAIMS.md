`PRIVACY_POLICY.md` and `STORE_LISTING.md` make statements about behaviour. Each one is listed here
with the code and test that back it, so that a release reviewer can check the documents against the
product instead of trusting either. Update this file in the same change as any behaviour or document
edit. First written 2026-10-11; revised the same day after an independent audit (findings F-01 to
F-22, cited where they changed a row).

Status:

- **verified**: an automated test that is wired into `ci.yml` exercises it (test file and name
  given). See the evidence caveat below: it does not mean a green run has executed it;
- **by design**: enforced by the manifest, CSP or types and asserted on every build by
  `scripts/check-build.mjs` or `scripts/check-release-docs.mjs`;
- **unit-only**: a unit suite covers it and an end-to-end test is not possible, or does not exist;
  the reason is given;
- **e2e-local**: an end-to-end spec in `tests/e2e` drives the behaviour in a loaded extension in
  real Chromium (Playwright's bundled build, not branded Chrome or Edge) and **passed in an
  agent-run local run on Windows (private build folder, one worker)**; no GitHub Actions run has
  confirmed it. It is evidence, not a promotion: it is written next to the row's own status
  (`unit-only; e2e-local`) and a row moves to `verified` only when a green Actions run URL is
  recorded in it. That a local run passed is what the agent that ran it reported; this pass read the
  specs and did not re-run them. No spec sees Chrome's native permission prompt: the e2e build's
  manifest holds the loopback hosts as required permissions;
- **in progress**: the code exists, but the shipped UI and end-to-end behaviour still have to be
  checked. **Do not publish a statement in this state until it moves to verified or manual.**
- **fix in progress**: the document says what the code does today, and another change is under way
  that will alter it. Re-read the row and the document when that change lands. No row carries this
  status after the second pass of 2026-10-11: each former one either landed (and is `unit-only`
  below) or is `open`;
- **open**: the document says what the code does today and the code is not what the claim or the
  product's own screens need; no change is in the working tree. The open-items list names the file
  and the string;
- **manual**: only the manual checklist (`docs/MANUAL_TEST_CHECKLIST.md`, row id given) can check it.

A `unit-only` row means: the test file named was read by the author of this revision and its
assertions cover the claim. This pass did not run it. The `unit (vitest)` job of Actions run 38130710828
(below) ran the whole Vitest suite at commit `ff0377f` and concluded `success`, so those suites
passed in CI at that commit; this pass did not check each named test in the job log, and a test
added after that commit has no CI run. Test titles are quoted exactly so that a reviewer can find
them.

**Evidence caveat (F-01).** The only CI evidence recorded here is the last run, read with `gh run
view` on 2026-10-11: <https://github.com/jerryboganda/studyvaultai/actions/runs/38130710828> (branch
`ci/wave-c`, commit `ff0377f`, conclusion **failure**). In it `static (lint)`, `static (typecheck)`,
`static (format)`, `unit (vitest)`, `build (prod + e2e + zip)` (including the release gate and the
store-document permission check), `audit (advisory)` and `stress (perf suites, SV_PERF=1)` concluded
`success`; **seven of the eight `e2e` shards failed** (one Windows shard passed) and `ci-ok` failed.
On Ubuntu the first-attempt failures included the earlier versions of `ai.spec.ts` ("accessibility"),
`dashboard.spec.ts` ("perf: 10,000 highlights", "bulk: selection and actions" > "move"),
`pdf.spec.ts` ("private windows" > "a reader opened from a private tab ...") and eight tests of
`sync.spec.ts`; the Windows shards were not itemised by this pass. Those specs have been changed
since (the working tree holds uncommitted edits to `ai`, `backup`, `sync`, `pdf` and `dashboard`
specs and their helpers) and **no Actions run has executed the changed versions**. Every completed
`ci.yml` run listed by `gh run list` (11 runs, all `CI`, all `failure`) failed overall, and
`release.yml`, `reproducible-build.yml` and `stress.yml` have never run. A row marked **verified**
therefore means "a test exists and is wired in", not "this has been proven in a green pipeline"; a
row marked `e2e-local` has an e2e spec that passed locally and has not passed in CI. Rows were not
promoted by this revision; none may be treated as publishable until its run URL is recorded here.
The e2e specs that exercise the second-pass hardening drive the reader with `?incognito=1` (not a
real private window), plant the pre-update copy (a real upgrade is not driven) and cannot see
Chrome's native permission prompt.
