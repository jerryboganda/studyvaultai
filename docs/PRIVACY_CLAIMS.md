# Claims ledger: what the store documents say and what proves it

> **DRAFT: describes intended behaviour; not for publication until every docs/PRIVACY_CLAIMS.md row it depends on is `verified`.**
>
> This ledger is the gate for that sentence. Revised 2026-10-11 against the working tree (second
> pass, after the hardening changes S1 backup and import, S2 PDF reader privacy, S3 redaction and
> purge, S5 search index, S6 database lifecycle and S7 sync; `docs/adr/010-module-seams.md`
> amendments 1 and 2, `THREAT_MODEL.md` section 7).

`PRIVACY_POLICY.md` and `STORE_LISTING.md` make statements about behaviour. Each one is listed here
with the code and test that back it, so that a release reviewer can check the documents against the
product instead of trusting either. Update this file in the same change as any behaviour or document
edit. First written 2026-10-11; revised the same day after an independent audit (findings F-01 to
F-22, cited where they changed a row).

Status:

- **verified**: an automated test that is wired into `ci.yml` exercises it (test file and name
  given). See the evidence caveat below: it does not mean a green run has executed it;
- **by design**: enforced by the manifest, CSP or types and asserted on every build by
  `scripts/check-build.mjs` or `scripts/check-release-docs.mjs`;
- **unit-only**: a unit suite covers it and an end-to-end test is not possible, or does not exist;
  the reason is given;
- **in progress**: the code exists, but the shipped UI and end-to-end behaviour still have to be
  checked. **Do not publish a statement in this state until it moves to verified or manual.**
- **fix in progress**: the document says what the code does today, and another change is under way
  that will alter it. Re-read the row and the document when that change lands. No row carries this
  status after the second pass of 2026-10-11: each former one either landed (and is `unit-only`
  below) or is `open`;
- **open**: the document says what the code does today and the code is not what the claim or the
  product's own screens need; no change is in the working tree. The open-items list names the file
  and the string;
- **manual**: only the manual checklist (`docs/MANUAL_TEST_CHECKLIST.md`, row id given) can check it.

A `unit-only` row in this pass means: the test file named was read by the author of this revision
and its assertions cover the claim; it was **not run** by this pass and **no CI run** has executed
it. Test titles are quoted exactly so that a reviewer can find them.

**Evidence caveat (F-01).** No row below records a CI run URL. On 2026-10-11, `gh run list` showed
every completed `ci.yml` run on the repository concluding `failure`, with the newest still in
progress; the independent audit found that no run has covered the working tree beyond static checks
and unit tests (F-01); and `release.yml`, `reproducible-build.yml` and `stress.yml` have never
executed (HTTP 404, "not found on the default branch"). A row marked **verified** therefore means "a test exists and is wired in", not
"this has been proven in a green pipeline". Rows were not promoted by this revision; none may be
treated as publishable until its run URL is recorded here. The hardening changes of the second pass
have had no CI run at all: their tests are unit and integration tests (Vitest, fake IndexedDB and
`fakeBrowser`, jsdom), and the one e2e spec that exercises any of them (`tests/e2e/pdf.spec.ts`,
"private windows" and the redirect test) drives the reader with `?incognito=1`, not a real private
window.
