`PRIVACY_POLICY.md` and `STORE_LISTING.md` make statements about behaviour. Each one is listed here
with the code and test that back it, so that a release reviewer can check the documents against the
product instead of trusting either. Update this file in the same change as any behaviour or document
edit. First written 2026-10-11; revised the same day after an independent audit (findings F-01 to
F-22, cited where they changed a row).

Status (a cell may carry two words when its claim has parts; each word applies to the part named
after it):

- **verified**: an automated test asserts it and passed in the cited Actions run, whose number the
  row records as "CI 38139836238". It is judged at the level the claim is made: for what the shipped
  extension stores, sends, shows or enforces that is a loaded-extension spec in `tests/e2e`
  (Playwright's bundled Chromium, headless, on Ubuntu and Windows, against the e2e build), and the
  row names the spec; for a rule or a constant (a length limit, a field's shape) it is the unit test
  that pins it. A `test.fixme` or skipped test did not run and is never evidence. What a passing
  spec does not assert is written in the row, not left to the reader;
- **by design**: enforced by the manifest, CSP or types and asserted on every build by
  `scripts/check-build.mjs` or `scripts/check-release-docs.mjs` (both ran in the `build` job of
  CI 38139836238);
- **unit-only**: only unit or integration suites assert it (jsdom, fake IndexedDB, mocked Chrome
  ports, the reference server in-process); the reason no loaded-extension spec does is given. Their
  files ran and passed in the `unit` job of CI 38139836238, which the cell says. That is not a promotion:
  the fakes stand in for the browser, the service worker or the server;
- **in progress**: the code exists, but the shipped UI and end-to-end behaviour still have to be
  checked. **Do not publish a statement in this state until it moves to verified or manual.**
- **fix in progress**: the document says what the code does today, and another change is under way
  that will alter it. Re-read the row and the document when that change lands. No row carries this
  status after the second pass of 2026-10-11: each former one either landed (and is `unit-only`
  or `verified` below) or is `open`;
- **open**: the document says what the code does today and the code is not what the claim or the
  product's own screens need; no change is in the working tree. The open-items list names the file
  and the string;
- **manual**: only the manual checklist (`docs/MANUAL_TEST_CHECKLIST.md`, row id given) can check it;
- **e2e-local** (retired by the fifth pass; no row carries it): a loaded-extension spec that passed
  in an agent-run local run on Windows with no Actions run behind it.

The 13 completed `ci.yml` runs before it all concluded `failure` and are not cited. What run
38139836238 does **not** prove, whatever a row says:

- branded Chrome or Edge: the specs drive Playwright's bundled Chromium; branded Chrome 137 and later
  ignores `--load-extension`;
- a real incognito window (`test.fixme`); the reader specs drive `?incognito=1`;
- Chrome's native host-permission prompt, accepting or declining it: the e2e build's manifest holds
  `http://127.0.0.1/*` and `http://localhost/*` as required host permissions, so no prompt appears, and
  that build also has an open overlay shadow root and an `e2e.settings.patch` message. Only
  `permissions.spec.ts` "production build" and `phase0-smoke.spec.ts` load the production build; the
  production zip is otherwise checked by the release gate;
- a hosted OpenID Connect provider over https (a stand-in over loopback http is used);
- a screen reader, forced colours, 400% zoom or any OS setting (axe and scripted keyboard checks only);
- the Chrome Web Store review, `release.yml`, `reproducible-build.yml` and `stress.yml` (none has ever
  executed) and the manual checklist (not run);
- a real schema upgrade: the pre-update copy is planted in the shape the product reads and is never
  made by an upgrade.

A row is publishable only when it is `verified` or `by design` in every part its statement relies
on; a row whose status cell still names a `unit-only`, `test.fixme`, `manual`, `open` or `in progress`
part is not. One spec is weaker than its title: `pdf.spec.ts` "addresses the reader refuses are
explained and never fetched" asserts each refusal message and the absence of an "Allow access"
control, and its zero-requests check is against the local fixture server, which none of the refused
addresses names (P1a).
